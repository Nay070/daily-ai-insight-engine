# 质量标准

这些标准是我给流水线设置的可执行质量门，不是报告完成后的人工勾选项。阈值的选择服务于三个目标：样本规模仍可人工复核、任何分析都能回到来源证据、单条失败不会污染整份日报。

## 数据覆盖

- 当前单次日报目标为 10–20 条有效新闻：可以覆盖多类来源，又不会超出逐条复核能力。
- 至少覆盖 3 种来源类型。
- 推荐同时包含中文和英文；若没有，运行清单必须披露。
- 标题、来源、URL、发布时间和正文/摘要为必填字段。
- 原始新闻通过规范化内容的 SHA-256 哈希精确去重。

## 结构化抽取

- Schema 最终通过率必须为 100%；无法修复的记录进入隔离区。
- 每条洞察至少包含 1 条关键事实及其原文证据。
- 每个证据片段必须能在规范化原文中逐字找到。
- 模型修复最多重试 2 次，禁止无限重试。
- `confidence < 0.60` 的记录不得自动进入日报；0.60 是当前自动入报下限，后续需要用人工标注样本校准，而不是视为永久常量。
- 摘要、影响理由、情绪理由和风险/机会必须使用中文。

## 事件聚合与排序

- 同一事件的重复报道只能占据一个 Top 事件位置。
- 每个事件必须保存其全部成员新闻 ID。
- 事件重要度采用公开、确定性的加权公式。
- 每个分项得分必须保留，不能只保存最终总分。
- 若多来源之间存在数字或结论冲突，必须记录在 `contradictions`。

## 报告

- Top 事件数量为 3–5 个，用有限篇幅集中读者注意力；其余事件仍保存在结构化数据中。
- 每个 Top 事件至少引用一个有效新闻 ID 和一个属于该事件的事实 ID。
- 每个 Top 事件必须显式包含背景和影响判断，并建立在事件事实与评分上。
- 必须分别给出技术、应用、政策、资本四方向趋势。
- 报告 Agent 只能读取验证后的事件摘要，不能读取整批原始文章。
- 执行摘要、Top 事件、趋势、风险和机会必须带事实 ID；事实 ID 必须能映射到来源新闻和逐字证据。
- 不得在报告中出现结构化数据不存在的新日期、数字或实体。
- 图表只读取通过验证的结构化数据。

## 可复现性与可观测性

- 版本化保存原始数据、所有 Prompt、Schema、最终输出和运行清单。
- 运行清单记录输入哈希、模型、Prompt 版本、Schema 版本、数量、失败、耗时和用量。
- 同一版本中的静态数据可以通过一条命令重新生成日报。
- 在线批处理必须逐条写检查点，并支持只重跑缺失或隔离项。
- 续跑必须同时匹配输入哈希、模型、Prompt 和 Schema 版本。
- 模型结果允许措辞波动，但事实集合、引用和排序规则必须可检查。
